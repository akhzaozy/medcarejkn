# Data sampel BPJS edisi 2025

Menu **Data BPJS** menyediakan katalog sumber, pemilihan kelompok dan jenis tabel,
distribusi kategori, tren bulanan, kamus variabel/kode, contoh detail, serta unduhan
Excel dan CSV lengkap. Tampilan ini membaca hasil ekstraksi lokal tanpa database PostgreSQL.
Data audit simulasi pada menu lain tetap memakai cakupan data sebelumnya.

## Ekstraksi dan ekspor

Gunakan Python dengan pandas dan Node dengan `@oai/artifact-tool` dari runtime dokumen.
Jalankan dari root proyek:

```sh
python3 scripts/bpjs/extract.py --source /lokasi/folder/2025 --output outputs/bpjs-2025
node --max-old-space-size=4096 scripts/bpjs/build-workbook.mjs outputs/bpjs-2025
```

Folder keluaran berisi:

- `analysis.json`: metadata, agregat seluruh baris, kamus kode, dan 100 baris pertama per tabel.
- `BPJS_2025_Analisis.xlsx`: dashboard dengan pilihan kelompok, tabel berfilter, kamus, dan contoh detail.
- `BPJS_2025_Detail_Lengkap.zip`: CSV semua file Stata, referensi Excel asli, dan metadata.

Proses membaca chunk 100.000 baris, mempertahankan kode sumber, memeriksa jumlah
baris terhadap header Stata, dan tidak mengubah file sumber. Arsip memakai UTF-8 BOM
serta tanggal ISO. Impor ID peserta/keluarga/kunjungan sebagai teks di Excel.
Tabel yang melampaui batas worksheet dapat diimpor lewat Power Query ke Data Model.
Builder membutuhkan ruang heap lebih besar saat mengekspor kamus dan agregat.

Backend mencari data di `outputs/bpjs-2025` secara default. Gunakan `BPJS_DATA_DIR`
untuk lokasi lain. Image backend menyertakan data demo, sehingga Portainer tidak
memerlukan bind mount folder sumber untuk mulai menampilkan pasien.
Jika ekstraksi belum tersedia, endpoint mengembalikan HTTP 503 tanpa data pengganti.

## API

- `GET /api/bpjs/catalog`: katalog semua tabel dan ketersediaan unduhan.
- `GET /api/bpjs/tables/:id`: ringkasan, variabel, kamus kode dan contoh tabel terpilih.
- `GET /api/bpjs/download/excel`: workbook analisis.
- `GET /api/bpjs/download/full`: arsip CSV lengkap.

## Pasien dan audit simulasi lomba

Menu **Audit Pasien** membaca indeks seluruh peserta, layanan, dan diagnosis sekunder.
Pilih kelompok, cari awal ID peserta, buka riwayat, pilih layanan, lalu jalankan
skenario bukti. Antrean menyimpan snapshot klaim, hasil pencocokan, catatan reviewer,
dan jejak perubahan di SQLite sehingga tetap tersedia setelah muat ulang atau restart.

Siapkan indeks dengan Python/pandas; backend memerlukan Node.js 22.13+ (Docker memakai Node 24):

```sh
python3 scripts/bpjs/build-patient-index.py --source /lokasi/folder/2025 --output outputs/bpjs-2025
```

`bpjs-patients.sqlite` adalah sumber baca saja. Hasil simulasi disimpan terpisah di
`outputs/bpjs-simulation/audit.sqlite`, atau folder `BPJS_AUDIT_DIR`. Identitas memakai
ID anonim sumber tanpa nama atau nama rumah sakit rekaan. Pencarian dan riwayat
selalu dibatasi kelompok data untuk menghindari pencampuran kelompok kontekstual.

Empat skenario memakai mesin rekonsiliasi bukti: belum tersedia, lengkap, sebagian,
dan tidak cocok. Dua komponen bukti demo adalah presensi dan catatan pelayanan.
Skenario tidak mengubah peserta, tanggal, diagnosis, atau biaya sumber. Biaya tagih
yang tinggi atau bernilai nol tidak otomatis dipakai sebagai label fraud BPJS.

Endpoint tambahan:

- `GET /api/bpjs/patient-catalog`
- `GET /api/bpjs/patients?cohort=Reguler&search=100&fkrtlOnly=true&after=`
- `GET /api/bpjs/patients/:cohort/:id?page=1`
- `GET /api/bpjs/encounters/:id`
- `GET/POST /api/bpjs/audits`
- `GET/PATCH /api/bpjs/audits/:id`

Daftar pasien memakai pagination berdasarkan ID. Antrean menampilkan 100 kasus
terbaru dan jumlah keseluruhan. Catatan telaah wajib diisi saat mengubah status.

## Arti angka

Angka yang ditampilkan adalah statistik sampel tanpa pembobotan. Edisi 2025 tidak
berarti seluruh tanggal layanan berasal dari 2025. Kelompok kontekstual dapat
bertumpang tindih dan tidak boleh dijumlahkan sebagai peserta nasional unik.
PSTV01 menghubungkan peserta dan layanan dalam kelompok. FKL02 menghubungkan
FKRTL dengan diagnosis sekunder pada relasi satu-ke-banyak. Agregasikan biaya
sebelum join agar biaya tidak terduplikasi. PSTV15 dipertahankan dalam detail,
tetapi belum digunakan untuk estimasi nasional.

Sumber KIA Anak tidak menyediakan tabel nonkapitasi. Null/string kosong dibedakan
dari kode sumber seperti MISSING. Selisih biaya tagih dan verifikasi tidak menjadi
label fraud; sumber ini tidak berisi bukti pelayanan aktual atau hasil investigasi.
`PSTV01_A` pada KIA Anak adalah ID peserta ibu dan dipertahankan sebagai pengenal,
tanpa menjadikannya dimensi kategori. Tanggal lahir setelah tahun sampel atau
sebelum 1900 ditandai untuk ditinjau; sumber tidak dikoreksi otomatis.


Uji ekstraksi memeriksa jumlah baris, ID duplikat/kosong, nilai nol, kode berlabel,

## Deployment Portainer

Bangun backend dari root repository (context `.` dan Dockerfile `backend/Dockerfile`).
Image menyertakan `analysis.json`, indeks pasien, manifest, dan workbook dari
`outputs/bpjs-2025`. Jangan memasang folder kosong ke `/app/bpjs-data`, karena
mount akan menutupi file yang sudah ada di image. Stack lama perlu dibangun ulang,
bukan hanya di-restart. Direktori audit tetap dipasang terpisah agar hasil telaah
bertahan setelah container diganti.

```sh
docker compose up -d --build backend frontend
curl --fail http://localhost:3765/api/bpjs/patient-catalog
curl --fail 'http://localhost:3765/api/bpjs/patients?cohort=Reguler'
```

Jika Portainer memakai image dari registry, bangun dan dorong image dari root
repository, lalu ubah tag pada stack. Jika memakai Git stack, gunakan commit terbaru
dan aktifkan rebuild image. Pertahankan konfigurasi jaringan/proxy domain yang sudah ada.

Indeks yang disertakan di repository adalah subset untuk demonstrasi, bukan seluruh
indeks lokal hasil ekstraksi. API daftar pasien melaporkan jumlah peserta yang benar-benar
tersedia pada indeks aktif. Agregat katalog sumber tetap mencakup seluruh data ekstraksi.
Untuk seluruh pasien, pasang folder hasil impor lengkap sebagai volume baca saja ke
`/app/bpjs-data`, dengan `BPJS_DATA_DIR=/app/bpjs-data`.

Pesan "indeks belum tersedia di server" berarti file tidak ditemukan pada direktori
terkonfigurasi. Backend tidak menjalankan impor otomatis saat halaman dibuka; klik
"Coba lagi" hanya memuat ulang data, sehingga pemasangan file harus diperbaiki dahulu.
